# Hermesによるフキダシ自律配置の中止記録

試行日：2026-10-17  
中止決定・記録公開：2026-10-21

**Hermesから漫画編集アプリを操作するための呼び出しが成立せず、自律配置の品質評価には到達しなかった。** 利用者の判断で、この独立した試作経路を中止した。

## 試そうとしたこと

登録済み38種類のフキダシ素材から選び、既存作品の複数フキダシについて位置・話者・発話種別などを調整して保存する。作品の読取、保存しないプレビュー、変更前のrevisionを確認した適用を独立CLIに用意し、Hermesの専用スキルから呼び出す構成だった。

現在の画面内エージェントが選択中のフキダシを編集する機能とは別経路だった。素材・輪郭・しっぽ・保存処理など、共通する既存機能の完成と、Hermesによる自律実行の成功は区別する。

## どこで止まったか

以下は整理前の保存ログから確認した内容。今回、モデルを再実行して結果を取り直してはいない。

| 試行 | 保存されたエラー・結果 | 確認できる停止点 |
|---|---|---|
| 最初のCLI起動 | `hermes: error: argument -z/--oneshot: expected one argument`。終了コード2、約1.36秒。 | `--oneshot`が要求する引数を渡せず、起動時の引数解析で停止。 |
| 既存原稿を対象にしたCLI起動 | `Unsupported gateway CLI options: --image, --run-budget.`。終了コード2。結果のモデル名は空、入出力tokenは0。 | 導入済みgateway CLIで非対応のオプションを指定していた。自律編集の依頼は実行されていない。 |
| gateway経由の画像添付 | `client.rpc('image.attach', ...)`が`hermes_cli.gateway_client.GatewayRPCError: request_failed`で失敗。 | 呼出元では画像添付が26行目、依頼実行の`view.run(...)`は33行目。依頼を実行する前の画像添付で停止した。保存ログには下位の失敗原因がなく、原因は特定できない。 |

照合した元ログ：`hermes-run.log`、`hermes-run-result.json`、`hermes-existing-run.jsonl`、`hermes-existing-run-result.json`、`hermes-existing-gateway.jsonl`、`hermes-existing-gateway-result.json`、および呼出元の`run_existing_gateway.py`。

## 結論と限界

失敗が確認されたのは、起動引数とgatewayへの接続・画像添付の段階。Hermesが素材を選択し、作品をまとめて編集して保存した成功記録はない。したがって、**「漫画を理解できなかった」「配置の質が悪かった」というモデル能力の評価はできない。** 記録された失敗から、自律配置そのものの成否を推定しない。

この記録から得られる改善点は、最初に起動・画像添付・応答の最小の往復を確認し、その後に保存しない提案、検証コピーへの適用、再読込と段階を分けること。通常UIや独立した部品の試験が通ることだけでは、Hermesの一連の処理が動く根拠にはならなかった。

## 中止時の整理方針

試作専用のCLI、編集モジュール、専用テスト、一時QA画面、導入済みスキル、作業用原稿・画像コピーは撤去対象。既存のフキダシ機能、素材、現行画面内エージェント、共通の保存処理、独立した回帰試験、利用者の原稿は保持する。

この失敗記録を公開先の正本とし、ローカルに失敗記録や試作の保管用コピーを残さない。原稿本文・画像、個人のローカルパス、セッション識別子は本記録に含めていない。
