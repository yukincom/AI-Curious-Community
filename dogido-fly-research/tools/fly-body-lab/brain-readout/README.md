# 固定ハエ回路の信号読出し学習 / 01

**接続グラフとLIF回路は固定し、その下流活動を読む小さな分類器だけを実際に学習した。** この学習実験は身体から独立して実施した。現在は[初回ライブ接続](../LIVE.md)で、身体の匂いから刺激した実回路の下流活動をこの固定読出し器に渡し、コードが寄り道目標を決める。LLM・Minecraftは未接続。環境の匂い・敵・mobを理解したという実験ではなく、人工的な匂い系／接近系刺激の識別実験。

## 実測結果

2026-09-16、取得済み176,422ニューロン・6,287,749接続の回路をJavaで実行し、228個の50 ms発火率窓を生成した。データ生成17.4秒、Java1 worker。うち168窓を学習に、別seedの60窓を評価だけに使った。

| 未学習seed・強度での評価 | 正解数 |
|---|---:|
| 匂い刺激中 | 16 / 16 |
| 接近刺激中 | 16 / 16 |
| 初めから無刺激 | 12 / 12 |
| 接近刺激を切った後 | 8 / 8 |
| 匂い刺激を切った後 | **0 / 8** |
| 全体 | 52 / 60（86.7%） |

クラス別再現率の平均は90.5%。常に学習側の最多クラスnoneを答える比較は46.7%。**匂いを切ってから100 msの残留活動を、8窓すべてodorと誤認した。** 正解率だけを取り上げて「現在の匂いを確実に検知できる」とは言えない。

50 ms窓は同じ試行内で相関する。独立したテストseedは2個であり、60個の独立実験ではない。分類器の調整にテストを使っていない。残留活動への対応は次の別実験として扱う。

## 実験条件

- 上流固定コミット: `blendi-remade/fly-brain-minecraft` @ `6cfa30175003ef25da68a237d5eda958f8047b82`。
- `Connectome`, `PopulationIndex`, `LifConfig`, `LifNetwork` の4つだけを未改変でコンパイル。固定コミット内容・同梱データSHA256を起動前に検証。
- dt=0.5 ms、全体gain=0.65、KC入力gain=0.25、worker=1。先行プローブのゲーム由来設定を使用。MotorDecoder、解析的SensoryEncoders、移動補助、学習則は回路に追加していない。
- 匂い: `prefix:ORN_DM1,prefix:ORN_VA2`。接近: `LC4,LPLC2`。入力は各ニューロンのポアソン発火率Hzを直接設定。
- 各seed・刺激・強度で回路を新規作成。刺激200 ms後、刺激を完全除去して100 ms継続。後半は活動が残っていても正解ラベルをnoneとする。最初から無刺激の300 ms試行も用意。
- train seed: `2026091601`–`2026091604`、刺激強度60/120/180 Hz。
- test seed: `2026091605`–`2026091606`、刺激強度90/150 Hz。seedと非ゼロ強度の両方がtrainと重ならない。
- 特徴: ALPN、KC、DNp01、DNp09、DNa02、下行集団、VNC運動集団、CB運動集団の8集団平均Hz。直接強制発火させる入力ニューロンが特徴集団と重ならないことをJavaで検査。
- ラベル・seed・刺激強度・phase・trial・time・wall時間は学習特徴にしない。学習データだけからlog1p変換後の平均と標準偏差を算出。
- クラス重み付き多クラスロジスティック回帰。ゼロ初期重み、1200回の全データ勾配更新、学習率0.08、L2=0.002。テスト結果を見てハイパーパラメータを変更していない。

## 再実行

JDK 25とPython 3標準ライブラリだけ。依存追加なし。研究リポジトリのルートからの例（配置が違う場合はスクリプトのパスを合わせる）:

```sh
python3 tools/fly-body-lab/brain-readout/train_readout.py .fly-research/upstream/blendi-remade--fly-brain-minecraft --output .fly-research/readout-training
```

同じ結果フォルダに対して `--reuse-data` を付けると、データSHA256を確認して分類器だけ再fitする。生成Javaの実行上限は180秒。CSVの実行時間列はマシン負荷で変わるため、同じseedでもCSV全体のハッシュは変わりうる。

この納品フォルダ内で検証:

```sh
python3 -m unittest -v test_readout.py
```

4検証は、保存重みから全heldout予測を再現、seed/強度の分離、実更新による学習損失減少、欠けた/非有限/負の入力拒否を確認する。テストは同梱`results/`を読む。

## 推論と成果物

`infer_readout.py MODEL_JSON` は標準入力から、`model.json`の`features_hz`にある8キーのHz値をJSONで受け取る。返すのはnone/odor/loomの確率と分類、残留活動に関する制限。指定した固定回路設定の50 ms窓でのみ評価済み。worldのセンサー値を神経発火率と偽ってこの入口に渡さない。

`results/`:

- `dataset.csv`: 228窓の実測値、刺激とラベル、seed、計算時間。
- `dataset-metadata.json`: 上流/データ/Javaラッパー/CSVのハッシュ、設定、実行時間。
- `model.json`: 実学習した重み、標準化係数、特徴順、設定、学習損失。
- `report.json`: train/test指標、混同行列、phase別評価、限界。
- `heldout-predictions.json`: 全heldout窓の予測と確率。
- `run.log`: 実行した各試行と集団サイズ。
- `classes/`: 再生成可能なJavaコンパイル出力。Gitに入れる必要はない。

匂い刺激後の残留を「今も匂う」という外界の断言へ変換してはいけない。次は長めの刺激除去試験や過去窓を使う読み出しを、新しい未使用seedで評価する。今回の失敗を隠す目的でテストラベルを付け替えたり、外部センサーを特徴へ混ぜたりしない。

親エージェントも回路のデータ生成から学習まで独立に再実行し、実行時間列を除く全228窓、学習重み、評価結果の一致を確認した。
