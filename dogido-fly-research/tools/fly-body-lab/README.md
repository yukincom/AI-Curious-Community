# ドギドの飛行ラボ

手足のない丸い身体で、飛ぶ・感じる・記録するための独立した3D実験室。LLMやMinecraftには接続しない。浮遊・追従の第1段階、柱回避の第2段階、歩く相手への先読み追従の第3段階を選べる。固定ハエ回路へ身体の匂いを送り、下流の反応を寄り道のきっかけに使う初回接続を追加。姿勢・推進・柱回避は既存の学習済み制御器が担当する。

## 開く

このフォルダの `start.command` をダブルクリックし、表示された [飛行ラボ](http://127.0.0.1:8767/) を開く。Python 3とWebGL対応ブラウザが必要。研究リポジトリのルートからも起動できる。

```sh
python3 tools/fly-body-lab/serve.py
# 8767が使用中なら別番号
python3 tools/fly-body-lab/serve.py --port 8768
```

終了はターミナルで Control+C。サーバーはこのフォルダだけを、このMac内の127.0.0.1へ公開する。外部CDN・LLMへの通信や本体設定の読み込みはない。Three.jsはMITライセンスを添えて同梱済み。

## 触って確かめる

起動時は「一緒に散歩する飛行［第3段階］」「自動で散歩する」「柱1本」。プレイヤーは柱の周りを自動で歩き、ハエ君が追従する。「柱の向こうへ呼ぶ」やリセットでも自動移動を維持する。第1・第2段階と比較可能。「ハエ回路とつながる」で「反応で寄り道する」が初期設定。匂いを切る、または「神経活動だけ観察する」に切り替えて比べられる。[接続の実測と限界](LIVE.md)。飛行自体については[第3段階の実測と限界](training/STAGE3.md)。


1. 「その場で浮く」でプレイヤー上空の高さ3.2 mを維持する。「気流あり・なしを30秒ずつ比較」は**画面の調整値によらない標準条件**を別々に計算する。
2. 上昇気流を切ると必要な上向き推進が増える。プレイヤー・他プレイヤー・村人の気流は個別調整できる。
3. 「ハエ君を自分で操縦する」でWASD（世界の軸方向）・QE（身体の向き）・Space（最大推進）・Shift（推進停止）。画面の矢印を押し続けても水平移動できる。文字入力欄を離れて3D場面をクリックしてからキーを使う。
4. 室温を下げると同じ操作でも推進力が弱くなる。匂いの左右差・視認範囲はカメラではなく身体位置・向きが基準。
5. 「プレイヤーの動き」で「自分で動かす」を選ぶと、ハエ君は追従に切り替わる。WASD／矢印キーでカメラ基準の移動、Shiftで走る。画面上の矢印も押し続けて使える。「自動で散歩する」「その場で待つ」にも切り替えられる。手動操作中に神経モード・匂いの有無・神経リセットを操作すると、キーの入力先を3D画面へ戻すので、そのままWASD／矢印キーで動かせる。村人と他のプレイヤーは、少し休みながら自動で歩き回る。ハエ君の手動操縦を選ぶと、プレイヤーは待機に戻る。一時停止・最初からも使える。「最初から」は環境の調整値を保ち、身体・時間・記録・プレイヤー位置をリセットする。
6. 「記録を保存」でJSONをダウンロード。観測の出現・消失と環境変更を記録する。約5 Hz・直近1800サンプル、60 Hzで検出した直近300イベントであり、完全再生用の操作ログではない。

## 実装した条件

- 重力・抵抗・半径0.25 mの身体・部屋と壁への衝突。物理は1/60秒刻み。ゲーム向けの簡易力学で、生物の羽ばたきや流体の再現ではない。
- 相手の頭上に上向き加速度を作る。横へ吸着する力はない。労力は推進入力の二乗積分で、実際のエネルギー量ではない。
- `minecraft:player` / `minecraft:villager` と個体IDを保持。プレイヤーは種別だけでなく `ownerId` との一致で区別する。ラボの個体IDは仮の識別子。実Minecraft接続時は実UUIDを受け取る。
- 身体から8 m・水平270度の簡易視野と遮蔽物、左右の匂い濃度。相手の種別は世界が提供する情報で、画像から学習した識別ではない。匂いは壁を透過する距離減衰モデル。
- `source: body_sensor` の `entity_detected` / `odor_detected` 信号を出す。将来のLLM接続用の候補で、本体の現行スメルポリシーやイベント契約へはまだ渡さない。
- 低温時の推進低下、観測した個体への慣れと時間による回復、労力に応じた疲れをコードで定義。慣れ・疲れは記録のみで、探索方針や推進にはまだ使わない。プレイヤーに慣れても気流は弱くならない。

## 現在地と次の順序

| 段階 | 状態 / 受入条件 |
|---|---|
| 1. 身体と環境 | 実装済み。手動飛行、停止、基準浮遊・追従、衝突、省力比較 |
| 2. 身体の感覚と記録 | 実装済み。身体位置から観測、個体IDの区別、検知・消失・条件変更のJSON記録 |
| 3. 固定ハエ回路の校正 | [独立した刺激試験](brain-probe/README.md)を実行済み。匂い・接近刺激の差を確認。残留活動・飽和・処理速度は未解決 |
| 4. 小さな読出し器 | [独立した神経読み取り学習](brain-readout/README.md)を追加。固定回路は変更せず、別seed・強度と刺激後の無入力で評価。[仮想身体との初回接続](LIVE.md)で使用。LLMは未接続 |
| 5. 飛行学習 | [障害物なしの第1段階](training/README.md)と[柱1本の第2段階](training/STAGE2.md)を実行済み。第2段階は新しい32場面で無接触到達。[第3段階](training/STAGE3.md)は動く目標の24場面と10分場面で追従を評価済み。固定神経回路の下流反応による寄り道目標を追加。神経で推進を学習したものではない |
| 6. 好奇心・飽き | 状態の土台のみ。新規性あり/なしを比較し、寄り道・慣れ・帰還が変わるか検証 |
| 7. Minecraft / LLM | 未接続。基礎が成立してから別のアダプターで接続。川柳中はその場所で停止または緩く追従するコードへ引き渡す |

[継続刺激と残留活動の読出し実験](brain-temporal/README.md)も実行済み。時間履歴を加えて刺激除去後の正判定は8.9%→45.4%に改善したが、採用条件を満たさずライブへの置換はしていない。

神経回路の刺激試験で活動が出たことと、感覚の意味を学習したことや飛べたことは区別する。神経試験は身体のシミュレーション時間とは別に進める。

## 検証

```sh
node --check tools/fly-body-lab/viewer.mjs
node --test tools/fly-body-lab/sim.test.mjs tools/fly-body-lab/input-state.test.mjs tools/fly-body-lab/neural.test.mjs tools/fly-body-lab/training/*.test.mjs
```

31テストで省力比較、温度、遮蔽、衝突、個体ID、停止・リセット、短い検知、環境変更の記録を確認。人物が静止した標準条件の30秒比較では、両条件で高さ3.2 m・接触0回、労力10.80 → 約1.45（約87%減）。これは設定した場と基準制御の検証値で、学習効果ではない。

ブラウザでも3D表示、気流比較、停止・再開、手動の推進停止による着地、低温設定、追従モードへの切替、プレイヤーのキー移動、村人と他プレイヤーの自動散歩を確認。神経回路の再現コマンドと実測の限界は別のREADMEを参照。
