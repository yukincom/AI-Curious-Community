# NDLOCR-Lite v2.0.0 と現行漫画ネームOCRの比較

測定日: 2026-11-24。

この文書では、[2026年8月のページ全体比較](2026-08-experiment-conditions.md)と同じ33ページ（通常評価32ページ＋ストレステスト1ページ）を対象に、2026-11-24公開の **NDLOCR-Lite v2.0.0** と現行の漫画向けOCR構成（RT-DETRv4-X Manga109-s v2 ＋ Baberu OCR ONNX）を比較した集計結果を公開します。

作家別・ページ別の識別情報、原稿画像、参照本文、OCR出力本文、元ファイル名は一切含みません。集計CSVは [ndlocr-lite-v2-2026-11-24-summary.csv](../results/ndlocr-lite-v2-2026-11-24-summary.csv)、実行環境と条件の記録は [ndlocr-lite-v2-2026-11-24-run-metadata.json](../results/ndlocr-lite-v2-2026-11-24-run-metadata.json) を参照してください。

## 1. テスト条件と環境

- **ハードウェア／ランタイム**: Apple M4 Max (64 GiB)、macOS、Python 3.11.15、`onnxruntime 1.23.2` (`CPUExecutionProvider`)
- **比較対象（新）: `ndl-lab/ndlocr-lite` `v2.0.0`**（tag `2.0.0`、commit `1f3adc7af311af1ce4cbbd4d9089f30781d01313`）
  - レイアウト検出: `deim-s-1024x1024-261124.onnx`
  - 行認識: `parseq-ndl-24x256-30-tiny-499epoch-261124.onnx` / `24x384-50-tiny` / `24x768-100-tiny` の3段階カスケード
  - モデル容量: OCRのみ `150.1 MB`（同梱の表構造推定 `tablecenternet_s_800_v3.onnx` を含めると `177.3 MB`）
  - ライセンス: `CC BY 4.0` ＋ レイアウト検出バックボーンに DINOv3 License
  - 追加オプション検証:
    - `--enable-tcy`（縦中横オプション）は縦書き手書き吹き出しの文字認識を大きく崩したため、デフォルトの無効（`false`）で本計測を実施しました。
    - 異体字包摂（`apply_character_inclusion`）は33ページ中4ページで微小変化を生じ、全体 Micro CER は `68.1% → 68.2%` とほぼ不変でした。
- **比較対象（既存）: 現行アプリ本番構成**
  - 領域検出: `rtdetrv4-x-manga109s_v2` (`model.onnx`, `conf_threshold=0.2`, `238.6 MB`, `Apache-2.0`)
  - 文字認識: `Baberu OCR ONNX` (`vision_int4.onnx` + int8 decoder, `115.9 MB`, `Apache-2.0`)
  - 後処理: `usable_ocr_lines` およびページ種別・4コマ見出し判定（表紙判定の除外有無も別行で記録）
  - モデル合計容量: `354.5 MB`
- **評価対象**: 通常評価32ページ（参照文字数 `3,714`文字、内訳：鉛筆・生ネーム17／清書済み漫画9／清書済みデジタル手書き5／濃い手書きネーム1）＋ 低コントラスト・紙面劣化ストレステスト1ページ（`161`文字）。`全体` 行は通常評価32ページのみの集計であり、ストレステスト1ページを含みません。

### 実行モードの切り分け

NDLOCR-Lite v2.0.0 はページ全体の行検出と読み順整序を一体で行う設計のため、公平な比較ができるよう3系統で計測しました。

1. **フルページ単体**: ページ画像をそのまま NDLOCR-Lite v2 へ入力（NDL標準の XY-cut 読み順）。
2. **フルページ → 既存領域へ割当**: フルページ単体で検出・認識した行を、既存のRT-DETR文字領域（および2026-08評価用の保存済み吹き出し領域）へ中心座標で割り当て、漫画向けの読み順で並べ直して評価。
3. **バブルクロップ直入力**: 2026-08のBaberu／Paddle比較と同一の267個の切り抜き画像を NDLOCR-Lite v2 へ入力（DEIM未検出で0行になった23件に対しては、PARSeqカスケードへ直接渡すフォールバック結果も別行で計測）。

### 同一バブルクロップ 267件の比較（全33ページ）

- 空出力（未検出）件数: Baberu `1`件に対し、NDLOCR-Lite v2（raw）は `24`件（うち DEIM が行を1本も検出できず0件になったのが `23`件、PARSeqフォールバック発動後の空出力は `1`件）。
- 空白無視の完全一致件数: `23 / 267`件（フォールバック込み `24 / 267`件）。
- 出力文字数合計: Baberu `2,980`字 vs NDLOCR-Lite v2 `2,315`字（フォールバック込み `2,514`字）。
- 267バブル推論合計時間: Baberu `23.19`秒 vs NDLOCR-Lite v2 `80.89`秒（切り抜き単位で DEIM を毎回実行するため低速化）。

## 7. 結果から見えた構造的要因と採用判断

1. **漫画向けの検出網羅性と誤検出耐性**: NDLOCR-Lite v2 のレイアウト検出器は図書・一般手書き文書を想定しているため、鉛筆・生ネームや絵密度の高いページで吹き出しを取りこぼす（例として鉛筆ネームの1ページで全124字中1行しか検出できず順序不問 F1 `0.0%` となった例がある）一方、枠線や絵の陰影を誤検出し反復的な英数字列を出力して Macro CER を押し上げる（`88.3%`）現象が見られました。対して現行本番は漫画特化の `RT-DETRv4-X Manga109-s v2` を使うため、文字領域の取りこぼしが大幅に少なくなっています。
2. **手書き崩れ文字の認識力**: v2 は v1 に比べ手書き文字の改善が見られる（バブル割当で v1 に対し `16勝-12敗-4分`）ものの、清書済みデジタル手書きや鉛筆ネームでは Baberu OCR に及びませんでした（鉛筆・生ネーム Micro CER: 現行本番 `67.5%` vs v2 フルページ `78.1%`、清書済みデジタル手書き: `40.9%` vs `68.5%`）。
3. **NDLOCR-Lite v2 が有利だった場面**: 濃い手書きネームの1ページでは文字認識自体は順序不問 F1 `80.1%`（現行 `86.4%`）まで迫りましたが、XY-cut 読み順がコマの横並びと合わずフルページ CER は `66.2%` まで悪化しました（RT-DETR 枠へ割り当て直すと `28.9%`）。また、清書済み漫画のうち活字の長い複数行セリフが続くページでは、224×224 一括で読む Baberu よりも1行ずつ分割して読む NDLOCR-Lite v2 の方が正確になるケースが確認されました。
4. **バブル切り抜き後の置き換え不適**: RT-DETR の切り抜きだけを NDLOCR-Lite v2 に置き換えても、小面積クロップに対する DEIM の検出漏れや推論時間増（267件で `80.89秒` vs Baberu `23.19秒`）が起きるため、差し替えは逆効果でした。

**判断**: 漫画制作ツールの現行デフォルトOCRは、精度・手書き耐性・誤爆耐性・ライセンス整合性（Apache-2.0）のいずれも上回る **`RT-DETRv4-X Manga109-s v2 + Baberu OCR` を維持**し、`NDLOCR-Lite v2.0.0` への移行は見送ります。
