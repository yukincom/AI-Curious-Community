# 評価コード

Python 3.10以上、標準ライブラリだけを使います。入力をネットワークへ送りません。標準入力から手元のデータを読み、集計数値だけを標準出力へ返します。

入力は次の形式のJSON配列です。以下は合成した説明用データです。

~~~json
[
  {"reference": "abc", "prediction": "axc"},
  {"reference": "def", "prediction": "def"}
]
~~~

~~~sh
python3 scripts/evaluate.py --mode page < private-input.json
python3 -m unittest discover -s tests
~~~

公開される原資料やサンプル原稿はありません。自分で用意した正解と出力を、採点単位ごとにあらかじめ対応付けてください。未認識の単位はpredictionを空文字にします。欠落した単位を入力から外すと、見かけのスコアが改善してしまいます。

## モード

| mode | 単位 | 処理 |
| --- | --- | --- |
| page | ページ | 正解・出力の両側へNFKCと空白除去 |
| bubble-raw | 吹き出し | 両側の空白除去のみ |
| bubble-normalized | 吹き出し | 出力側だけNFC＋全角ASCII変換、両側の空白除去 |

bubble-normalizedでは、正解をあらかじめ基準表記で用意します。出力だけを変換する、保存済み評価器と同じ非対称な条件です。

集計する入力を分けることで、条件別の結果を算出できます。複数のOCR方式や通常評価とストレステストを混ぜて渡さないでください。

## 出力

input_items、scored_items、skipped_empty_reference_items、文字数、編集距離、完全一致数、micro/macro CER、LCS由来のmicro/macro文字F1を返します。pageではmacro句読点中立CERも返します。F1と句読点中立CERの定義は[実験条件](2026-08-experiment-conditions.md)に記載しています。

CER・F1は百分率ではなく比率です。CER 0.25は25%、CER 2.0は200%です。

正規化後の正解が空になる入力はスキップし、その件数を明示します。採点対象が0件の場合、値は0と出力されるためscored_itemsも必ず確認してください。元の吹き出し評価器が空正解を扱う場合の挙動とは異なりますが、公開結果の非空正解を用いた採点には影響しません。

本文、入力パス、任意ラベル、対応ID、文字の誤り対、個別ページの結果は出力しません。入力形式のエラー時も入力本文を表示しません。許可する入力キーはreferenceとpredictionだけです。

## 検証範囲

公開コードは、8月の保存済みページ別データにローカルで適用し、全42行の集計値と一致することを確認しました。10月14日のGemma4 26B-A4B比較についても、初回・再測定それぞれ29ページ×Gemma/Baberuの計116件で、保存された文字数・編集距離・CERとの一致を確認しました。10月の集計は[既存の構成比較CSV](../results/bubble-configuration-comparisons.csv)の末尾に追記しています。評価単位と採点条件は[10月の説明](2026-10-14-gemma-26b.md)を参照してください。

公開結果と同じ元データは配布しないため、第三者による同一データでの独立再計算はできません。

合成データのテストでは、NFKCと限定的な全角変換の違い、LCSの順序、micro/macro集計、100%を超えるCER、空正解の件数、数値のみの出力を確認します。
