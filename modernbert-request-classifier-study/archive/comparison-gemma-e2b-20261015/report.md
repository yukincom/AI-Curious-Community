# Gemma 4 E2Bと採用ModernBERTの199件比較

**実施日：2026-10-15。** 同じ199件で精度を測定し、速度は199件×5周＝995計測／モデル。全応答と計時を保存し、推論を追加せず再検算した。

E2Bは既存キャッシュの `lmstudio-community/gemma-4-E2B-it-MLX-4bit`。ModernBERTは採用済みv1.8 / seed 44（628件で学習した保存重み）。準備済み778件による再学習は実行していない。

## 全体結果

| 指標 | ModernBERT 30M | Gemma 4 E2B |
|---|---:|---:|
| 厳密5分類の正解率 | 86.93%（173/199） | 71.36%（142/199） |
| 会話2分類を併合した4経路の正解率 | 87.94%（175/199） | 78.39%（156/199） |
| 5分類のmacro-F1 | 0.8750 | 0.6847 |
| 1依頼の中央値 | 3.29 ms | 201.88 ms |
| 1依頼の平均 | 3.85 ms | 203.31 ms |
| 1依頼の95パーセンタイル | 7.25 ms | 215.65 ms |

中央値の比はE2BがModernBERTの 61.3倍。**CPU分類器の直接呼出しと、MLX/GPU生成モデル＋ローカルHTTPの経路全体の比較**であり、同一デバイス上のモデル単体の速度比ではない。

## 固定した条件

- 同じ本文・履歴を既存 `dataset.model_example()` で整形。正解・ID・タグ・旧予測はモデルへ渡さない。既存Jev比較の質問と5候補をそのまま使い、E2Bには承認済みの「labelだけを1行で出力」を追加した。
- ModernBERT：CPU、float32、SDPA、PyTorch内4スレッド／相互1スレッド。E2B：MLX/Metal、テキストのみ、標準 `mlx_lm.server` を127.0.0.1:8081で実行。配布名は4bitだがMLPに105個の8bit設定を含む。
- E2B：temperature=0、seed=0、最大32 token、thinking無効、各リクエストは1件。prefix cacheを0件に設定し、全成功応答でcached_tokens=0と入力token数を検査。モデル・カーネルはウォームアップする。
- 外側の空白を除去した5ラベルの完全一致だけを受理。説明文・余分な文字・生成打切り・通信失敗は不正出力として分母へ残す。修復、既定ラベルへの補完、再試行はしない。
- 各モデル20件のウォームアップ→199件の精度測定→速度5周。各周は同じ乱数で並べ替え、モデル順を交代。各ブロック直前に4件の追加ウォームアップ。
- 計時は入力整形からラベル決定まで。E2BではJSON変換、新規TCP接続、HTTP、キュー待ち、生成も含む。起動・モデル読み込み・ウォームアップ・結果保存・検算は含めない。
- 入力切り詰め0件。ModernBERTは18〜154 token、E2Bは376〜527 token。承認済みprompt SHA-256：`a5afda11dec8a7d44279a337d975b560b3ccdb36b50ab418d9ed394c99744ff1`。
- ModernBERTの全199予測は前回と一致。元データ・両モデル・承認プロンプトのハッシュも一致。E2B revision：`31512dab743c73974a99795270031a6f85072d94`。
- 開始前の確認で8080が準備時PID 17167から16636へ変わっていたため、初回の起動を実験ファイル作成前に中止。現在のQwen3.6-35B-A3Bを読み取り確認し、PID 16636を測定開始から終了まで維持した。8080へのモデル呼出し、停止、再起動、切替は行っていない。
- 比較用8081（PID 23759）は測定後に終了。既存の優先制御brokerを使わない標準サーバーで実行。本体への分類器接続は行っていない。
- メモリや常駐サービスの状態はresources.jsonlに保存。既存サービスが動いた共有Macでの測定であり、バックグラウンド負荷を除いた専用機の値ではない。

## 解釈の範囲

- 199件は合成193件・観測発話5件・ユーザー作例1件。movingはseed選択、regressionは既知の失敗分析で参照済みの診断群。完全な未知評価や実会話の発生頻度を代表する標本ではない。
- ModernBERTはこの5分類用に学習済み。E2Bはドギド向けの追加学習なし。今回の固定プロンプト・量子化モデル・thinking無効という条件での成績であり、E2B全般の能力は判定しない。測定後のプロンプト調整や再試行もしていない。
- 4経路の補助集計はnot_requestとother_requestだけをconversationへ併合する。厳密5分類の正解は変更しない。
