# 23分類：ドギド呼び寄せ・剣の誤分類調査（2026-10-22）

**後続：[剣の基本例復帰と呼び寄せ・召喚の合成例追加](2026-10-22-request-classifier-action-augmentation.md)。650件を準備し、[学習結果を受領・照合済み](2026-10-22-colab-23class-650-results.md)。以下は旧536件の調査記録。**

受領済みColab結果の誤分類、実際に重み更新へ使ったtrain、過去のv1.9、epochごとのdev成績を照合した。追加の推論・学習は行っていない。

## 結論

**教材の間引きと分割を組み合わせたときの表現の不足、重点用途の低下を見落とすモデル選択を確認した。** どちらがtestの各誤りへ何割寄与したかは、この1試行では確定できない。

- 剣のユーザー作例10件は、全件が今回のtrainに残り、全件正解している。
- ただし旧trainの剣140件から、今回のtrainは25件に減った。「装備」「つるぎ」「鉄」「ダイヤ」「ネザライト」を含む剣の正例がtrainに0件になっていた。類例の代表を残しても、その代表群を評価側へ置くと学習されない。この確認が教材準備に欠けていた。
- ドギドのtrain15件は観測発話13件・合成2件。「おいで」が8件、「ついて」が4件で、表現が偏っている。ただし誤分類文に非常に近い正例も学習済みであり、単純に作例がなかったとは説明できない。
- **epoch5のdevでは剣5/5・ドギド3/3。選択されたepoch10では剣1/5・ドギド2/3。** 全23分類のmacro F1だけで選んだため、視線11分類の改善がこれらの低下を上回った。
- 「飼っている猫を呼んで。」の正解は対応外の`not_target`。乗り物呼び出しへ予測したモデルの誤りであり、猫を呼べる教材にはしていない。

## 途中でできていたものを、選抜時に落としている

これは同じdevに対する同じ試行内の記録。testの再評価ではない。

| 指標 | epoch5 | 選択されたepoch10 |
|---|---:|---:|
| 剣の正解 | 5/5 | 1/5 |
| 剣と予測した中の正解 | 5/9 | 1/1 |
| ドギドの正解 | 3/3 | 2/3 |
| 乗り物の正解 | 5/5 | 5/5 |
| 乗り物と予測した中の正解 | 5/5 | 5/7 |

| dev loss | 1.5084 | 2.1226 |

epoch5→10の全体macro F1への寄与を分解すると、視線11分類が+0.1171、残る12分類が−0.0544、合計+0.0626。方向ごとに別ラベルなので、視線だけで全体平均の11/23を占める。重点用途ごとの成績低下を止める条件は置いていなかった。

**同じ教材で剣のdev5/5へ到達していたため、「装備という学習文がないから必ず失敗する」とは言えない。** 教材の弱点に加え、学習後半での汎化の悪化と、全体平均による選抜を分けて扱う必要がある。train最終379/379・最終epochのtrain loss約0.00000174に対し、dev lossはepoch4の1.3977から最終2.1226へ上昇している。これは過学習と整合するが、学習率・回数・データ配分の寄与を切り分けた実験はまだない。

epoch5も剣の誤検出4件があり、より良い本番モデルだったと断定はしない。epoch5のtest予測はなく、保存重みも最良更新のたびに上書きされ、受領ZIPにはepoch10だけがある。epoch別記録（未収録・実験元参照: `../artifacts-v3-pilot536/reports/trial-1-dev-history.jsonl`）、選択処理（未収録・実験元参照: `../dev_tools/request_classifier/train.py`）。

旧v1.9 seed43の保存済み比較では剣32/35（91.4%）。今回の23分類モデルは、旧v1.9の重みを引き継がず、同じ基盤モデルから新しく全体を微調整したもの。剣140件を含む旧train778件と、剣25件を含む今回train379件は異なる。[旧比較](../comparison-v19-cpu/report.md)、今回の学習条件（未収録・実験元参照: `../artifacts-v3-pilot536/reports/protocol.json`）。

## 猫の確認

「飼っている猫を呼んで。」は、旧`other_request`から今回の`not_target`へまとめた対応外依頼。正解ラベルに問題はない。testに1件あり、trainには猫など呼べない動物の呼び出し例がない。モデルは乗り物をほぼ1.0のスコアで予測した。乗り物名と「呼ぶ」の違いを一般化できていない例として扱う。ゲーム側で猫を呼び出せたという記録ではない。

## 次の修正方針

1. 既存の間引き資料から、装備・つるぎ・素材指定・引用後の実依頼など、基本表現を再点検する。ユーザーへ追加作例を求める前に、手元の教材の欠落を直す。
2. 原文・正解ラベルを保持し、train内の表現の幅と用途の区別を確認する。今回の誤答をそのままtrainへ移して同じtestの精度向上を主張しない。
3. 23ラベルの出力は維持しつつ、選抜時には重点用途ごとの適合率・再現率も確認する。方向を8分類へ分けたことだけで、剣や呼び寄せの低下が平均に埋もれない選択規則を、次回実行前に決める。

今回の調査では教材・分割・学習設定・採用モデルは変更していない。
